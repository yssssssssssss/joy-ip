# 超时时间优化：90秒重连机制

## 修改日期
2026-01-21

## 修改目标
1. **前端**：保持无限等待（`timeout: 0`），不会因超时报错
2. **后端**：将所有生成环节的超时从600秒（10分钟）改为90秒，超时后自动重连

## 修改原因
- 服务器不稳定，长时间等待（10分钟）会导致用户体验差
- 90秒超时后重连可以更快地发现问题并重试
- 前端无限等待确保不会在后端还在运行时报错

## 重试机制说明
项目已有三层重试机制（详见 `RETRY_MECHANISM_GUIDE.md`）：

1. **HTTP客户端层** (`utils/http_client.py`)
   - 自动重试3次
   - 指数退避：1秒、2秒、4秒
   - 处理429/500/502/503/504错误

2. **应用层** (`banana-pro-img-jd.py`)
   - 重试3次
   - 指数退避：2秒、4秒、8秒
   - 现在每次重试的超时为90秒

3. **控制器层** (`generation_controller.py`)
   - 重试1次

## 预期效果
1. ✅ 前端永不超时，持续等待后端响应
2. ✅ 后端每个请求90秒超时，超时后自动重连
3. ✅ 结合重试机制，单个请求最多尝试 90秒 × 3次 = 270秒（4.5分钟）
4. ✅ 更快发现网络问题，更快重试
5. ✅ 提升用户体验，减少长时间等待

## 验证方法

grep -r "timeout=600" --include="*.py" .

## 注意事项
1. 如果服务器响应时间经常超过90秒，可能需要：
   - 增加重试次数
   - 或者适当增加超时时间（如120秒）
2. 前端的无限等待依赖于轮询机制，确保轮询间隔合理（当前为1-2秒）
3. 监控日志中的超时和重试情况，根据实际情况调整

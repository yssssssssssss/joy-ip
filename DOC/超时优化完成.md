## 工作原理

### 前端流程
```
用户发送请求 
  ↓
前端发起API调用（timeout: 0，无限等待）
  ↓
持续轮询后端状态（每1-2秒）
  ↓
直到后端返回结果或用户取消
```

### 后端流程
```
接收请求
  ↓
调用外部API（timeout: 90秒）
  ↓
如果90秒内成功 → 返回结果
  ↓
如果90秒超时 → 自动重试（最多3次）
  ↓
重试成功 → 返回结果
重试失败 → 返回错误
```

## 重试机制
项目已有三层重试机制：

1. **HTTP客户端层** - 自动重试3次（1秒、2秒、4秒间隔）
2. **应用层** - 重试3次（2秒、4秒、8秒间隔）
3. **控制器层** - 重试1次

**单个请求最长时间**: 90秒 × 3次 = 270秒（4.5分钟）

## 优势

### ✅ 相比之前的10分钟超时
1. **更快发现问题**: 90秒 vs 600秒
2. **更快重试**: 发现超时后立即重试，而不是等10分钟
3. **更好的用户体验**: 用户不会等待过长时间
4. **更高的成功率**: 多次短时间重试比一次长时间等待更可靠

### ✅ 前端无限等待的好处
1. **不会误报错**: 后端还在运行时，前端不会因为超时而报错
2. **适应不稳定网络**: 即使网络波动，前端也会持续等待
3. **用户可控**: 用户可以随时取消请求，而不是被强制超时

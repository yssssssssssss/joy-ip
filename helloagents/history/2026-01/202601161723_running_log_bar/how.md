# 技术设计: 生成流程运行日志条（输入框上方）

## 技术方案

### 核心技术
- **后端:** Flask / JobManager（沿用 `append_log`）
- **前端:** Next.js / React / Tailwind CSS（滑入动画 + 单行截断）

### 实现要点
- 后端在 `Job.to_dict()` 中新增 `latest_log` 与 `logs_count` 字段，来源为 `job.logs` 的最后一条与长度。
- 前端在生成链路的轮询中同步更新 `latest_log`，驱动日志条 UI 内容变化。
- 日志条展示策略：
  - `chatStatus in ('analyzing','generating') || isLoading` 时显示；
  - `chatStatus === 'preview'`（等待用户确认）时隐藏；
  - 任务结束（成功/失败/取消）后清空并隐藏。
- 兼容无日志场景：排队/刚启动时 `latest_log` 可能为空，前端显示“排队中/运行中/处理中…”占位文案。

## 架构决策 ADR
本变更为 UI 增强与接口字段补充，不引入 SSE/WebSocket；继续沿用现有轮询机制以最小化改动与风险。

## API设计

### [GET] /api/job/<job_id>/status
- **变更:** 在 `job` 对象中新增字段：
  - `latest_log: string | null`
  - `logs_count: number`
- **兼容性:** 保持原字段不变；新增字段为可选字段，前端需容错处理。

## 安全与性能
- **安全:** 日志内容仅用于展示任务进度，不包含敏感信息；前端仅只读展示，不提供编辑/上传。
- **性能:** 仅增加两个字段，避免每次轮询返回完整日志列表；前端对重复日志做去重，减少不必要渲染。

## 测试与部署
- **测试:** 本地手工回归关键链路（分析/排队/生成/取消/失败）。
- **部署:** 无额外依赖；后端与前端同时发布以获得最佳体验（仅后端更新不影响现有功能）。
